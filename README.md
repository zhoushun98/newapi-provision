# new-api 配置种子

把一套 new-api 的「供应商 + 模型元信息 + 计费配置」用一条命令灌进任何新实例，不用在 UI 里一个个点。

## 文件

- `seed.json` — 权威配置数据（从线上实例导出，可按需修改）：
  - 3 个供应商（OpenAI、Anthropic、xAI，含图标）
  - 21 个模型的元信息：名称、供应商归属、图标、简介、端点、匹配类型（不设标签）
  - `pricing`：21 个模型全部用计费表达式（`billing_setting.billing_expr` + `billing_mode`），系数直接是官方美元价：8 个 OpenAI 模型带 272K 长上下文分档，3 个 Grok 带 200K 分档，10 个 Claude 不分档（含 5 分钟 / 1 小时缓存写入价）
- `provision.py` — 幂等灌入脚本，标准库实现，无依赖。**要求 new-api v1.0.0-rc.40 及以上**（定价走按模型的 `/api/option/model_pricing` 接口，旧版本会在写入前直接报错退出）

## 用法

```bash
# 0. 改完 seed.json 先离线自检（不连实例）
python3 provision.py --check

# 1. 在目标系统：控制台 → 个人资料 → 生成访问令牌（需超级管理员账号，定价接口只对 root 开放）
# 2. 灌入（先 --dry-run 预览）
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --dry-run
python3 provision.py --base-url http://目标机:3000 --token <访问令牌>

# 全新系统建议加 --reset-pricing：清掉出厂自带的一大堆过时模型定价
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --reset-pricing --dry-run
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --reset-pricing
```

两种定价写入模式：

- **默认**：seed 里的模型整体替换为 seed 的定价（该模型在 seed 里没配的键会被清掉，比如旧的倍率），seed 之外的模型定价原样保留。适合往已经在用的系统里补配置。
- **`--reset-pricing`（清空重置）**：在默认行为之上，再把 seed 之外所有模型的定价清空（ERNIE、BLOOMZ、mj_* 等出厂默认、历史上删掉的模型、图片/音频倍率），只留 seed 的精确状态。适合初始化全新系统。⚠️ 目标系统上手工配过、但没进 seed 的定价也会被清掉——先 `--dry-run` 看清单。

所有定价变更合成**一个请求**提交：后端单事务写入、按模型整体校验，任一模型不合法则整批不生效。`--dry-run` 也会调用后端的预览接口把每份定价草稿校验一遍（不落库），表达式写错在预览阶段就能发现。

**可反复执行（幂等）**：供应商、模型、定价都是先比对、无差异就跳过，重复跑 N 遍结果一致，不会重复创建或反复写库。

## 注意

- **`--check` 自检**：`seed.json` 的数据纪律里能机器检查的部分都做了——每个模型都有表达式且 mode 为 `tiered_expr`、没有旧定价模式的键、有没有指向已删模型的孤儿键、Claude 每档都写全 `cr` / `cc` / `cc1h`（漏写缓存写入就不计费）、缓存写入价是否为输入价的 1.25x（5 分钟）/ 2x（1 小时）。灌入前也会自动跑一遍，不通过就不连实例。
- **供应商自动创建**：全新系统的供应商列表是空的，脚本会按 seed 自动补齐（按名称查重，已存在的不动、不覆盖你的手工修改）。
- **模型元信息以 seed 为准**：已存在的模型若描述、图标、标签、端点、状态、匹配规则或供应商绑定与 seed 不同，会被改回 seed 的值（UI 里手工改过的也一样）。脚本新建的模型会关闭「同步官方元数据」（`sync_official=0`），免得被上游同步覆盖掉 seed 的文案。seed 里省略的字段按空值处理，比如各模型都不写 `tags`，实例上已有的标签会被清空。
- **渠道不在种子范围内**（含上游密钥，不适合进仓库）——新系统需自行添加渠道，模型与渠道的绑定会自动关联。
- **币种约定**：当前收录的三家（OpenAI / Anthropic / xAI）全部按官方美元价填写，数字直入。注意系统本身不做汇率换算，若将来纳入非美元计价的厂商，需自行决定折算口径。
- **Grok 200K 长上下文阶梯**：短档 $2/$6，提示词**达到** 200K 时整个请求按 $4/$12 计费（不是超出部分才涨），所以表达式写 `len < 200000`（恰好 200,000 也属高档）。缓存命中各代不同：`grok-4.7` / `grok-4.6` $0.5/$1，`grok-4.5` $0.3/$0.6。
- `grok-4.7` 为 xAI 当前旗舰（2026-09-21 发布），`grok-4.6` 降为上一代、`grok-4.5` 为旧版；三者除 4.5 的缓存命中价外定价相同。
- `claude-opus-5-5` 为当前 Opus（2026-09-22 发布）：$4/$20，缓存写 $5、命中 $0.2（**0.05x**）。`claude-opus-5` 与 `claude-opus-4-8` 官方同价（$5/$25，缓存写 $6.25、命中 $0.5）。Claude 在 1M 上下文内按标准价计费，无长上下文溢价，故表达式只有一档。
- **Anthropic 描述按代际表述**（「当前 / 上一代 / 旧版」），不写死「最强」这类绝对说法——新一代发布时只需把上一档降级，不用重写整组文案。Opus 5.5 发布后 5 降为「上一代」，4.8 / 4.7 / 4.6 为「旧版」；Fable 5.1 发布后 Fable 5 降为「上一代」。
- Claude 缓存命中价不是全系 0.1x：`claude-fable-5-1` 是 **0.025x**（$0.25），`claude-opus-5-5` 是 **0.05x**（$0.2），其余型号仍是 0.1x。
- **`gpt-5.6` 全系按官方现价**：`sol` $4/$20（长档 $8/$30）、`terra` $2/$12、`luna` $0.2/$1.2（长档 $0.4/$1.8）。其中 sol 是**至少持续到 2026-11-21 的促销价**，到期后要回来复核。`codex-auto-review` 无官方价，跟 sol 同价。
- **GPT-6 一代**（2026-09 发布）：`gpt-6-astra` 旗舰 $10/$50（长档 $20/$75），`gpt-6-sol` $2/$10（长档 $4/$15），`gpt-6-luna` $0.1/$0.5（长档 $0.2/$0.75）；缓存命中均为 0.1x、缓存写入 1.25x（OpenAI 自 GPT-5.6 起收写入费，GPT-5.5 及更早不收）。长档是输入**超过** 272K 整单涨价，表达式写 `len <= 272000`。
- `claude-sonnet-5` 的 $2/$10 **已转为官方标准价**：原定 2026-09-01 涨到 $3/$15 的计划被 Anthropic 明确取消，无需再按限时价跟进。
- **后端内置计费表达式**：rc.40 自带 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`（图像计费用 `img` / `img_cr` 变量）和 `gpt-6-astra` 四条内置表达式，只作为默认值生效、不落库。脚本按模型写入不会把它们固化进库；`gpt-6-astra` 在 seed 里有显式定价，以 seed 为准。
- **从 seed 删掉条目 ≠ 目标系统会删**：已灌入实例的模型元信息和供应商需在 UI 里手工删；定价在默认模式下对 seed 之外的模型原样保留，只有 `--reset-pricing` 会清掉（连带清掉你手工配的其他定价，先 `--dry-run`）。
- **只用计费表达式**：rc.40 已把「按 Token（倍率）」「按次」两种旧定价模式标为弃用，表达式模式下计费不读倍率表，所以 seed 里没有 `ModelRatio` 等旧键（`--check` 会拒绝）。按次、图片、音频计费也都用表达式写（`fixed()`、`img`、`ai` / `ao` 变量）；分组倍率（GroupRatio）不是按模型的定价，不在脚本范围内。UI 里「转换为计费表达式」按钮对本仓库的模型会报 routing 校验失败（rc.40 只认 map 形式的 endpoints），不用管它。
- 配置有变化时，重新从线上导出或直接改 `seed.json`，然后对所有实例重跑一遍。
