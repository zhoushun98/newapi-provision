# new-api 配置种子

把一套 new-api 的「供应商 + 模型元信息 + 计费配置」用一条命令灌进任何新实例，不用在 UI 里一个个点。

## 文件

- `seed.json` — 权威配置数据（从线上实例导出，可按需修改）：
  - 5 个供应商（OpenAI、Anthropic、xAI、DeepSeek、Google，含图标）
  - 47 个模型的元信息：名称、供应商归属、图标、简介、匹配类型（不设标签、不设端点）
  - `pricing`：47 个模型全部用计费表达式（`billing_setting.billing_expr` + `billing_mode`），系数直接是官方价（DeepSeek 为人民币数字）：9 个 OpenAI 文本模型带 272K 长上下文分档，3 个 GPT Image 按张计费（$0.1/张），3 个 Grok 文本模型带 200K 分档，2 个 Grok Imagine 图片按张计费（$0.1/张）、3 个 Grok Imagine 视频按秒计费（$0.2/秒），12 个 Claude 中 `claude-haiku-5-5` 带 100K 分档、其余 11 个不分档（均含 5 分钟 / 1 小时缓存写入价），1 个 DeepSeek 不分档（一律按空闲价），14 个 Gemini（4 个基础型号 + 10 个思考档位变体，变体与基础型号同价）中 `gemini-3.1-pro-preview` 及其变体带 200K 分档、其余不分档
- `provision.py` — 幂等灌入脚本，标准库实现，无依赖。**要求 new-api v1.0.0-rc.40 及以上**，已对齐 rc.44（定价走按模型的 `/api/option/model_pricing` 接口，旧版本会在写入前直接报错退出）

## 用法

```bash
# 0. 改完 seed.json 先离线自检（不连实例）
python3 provision.py --check

# 1. 在目标系统：控制台 → 个人资料 → 访问令牌（需超级管理员账号，定价接口只对 root 开放）
#    rc.41 起令牌按权限授权：勾选「模型」与「系统设置」的查看 + 编辑
# 2. 灌入（先 --dry-run 预览）
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --dry-run
python3 provision.py --base-url http://目标机:3000 --token <访问令牌>

# 全新系统建议加 --reset-pricing：清掉出厂自带的一大堆过时模型定价
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --reset-pricing --dry-run
python3 provision.py --base-url http://目标机:3000 --token <访问令牌> --reset-pricing
```

两种定价写入模式：

- **默认**：seed 里的模型整体替换为 seed 的定价（该模型在 seed 里没配的键会被清掉，比如旧的倍率），seed 之外的模型定价原样保留。适合往已经在用的系统里补配置。
- **`--reset-pricing`（清空重置）**：在默认行为之上，再把 seed 之外所有模型的定价清空（ERNIE、BLOOMZ、mj_* 等出厂默认、历史上删掉的模型、图片/音频倍率），只留 seed 的精确状态。适合初始化全新系统。⚠️ 目标系统上手工配过、但没进 seed 的定价也会被清掉——先 `--dry-run` 看清单。

所有定价变更合成**一个请求**提交：后端单事务写入、按模型整体校验，任一模型不合法则整批不生效。`--dry-run` 也会调用后端的预览接口把每份定价草稿校验一遍（不落库），表达式写错在预览阶段就能发现。

**可反复执行（幂等）**：供应商、模型、定价都是先比对、无差异就跳过，重复跑 N 遍结果一致，不会重复创建或反复写库。

## 注意

- **`--check` 自检**：`seed.json` 的数据纪律里能机器检查的部分都做了——每个模型都有表达式且 mode 为 `tiered_expr`、没有旧定价模式的键、有没有指向已删模型的孤儿键、Claude 每档都写全 `cr` / `cc` / `cc1h`（漏写缓存写入就不计费）、缓存写入价是否为输入价的 1.25x（5 分钟）/ 2x（1 小时）、思考档位变体（如 `gemini-3.8-flash-high`）是否与基础型号同价。灌入前也会自动跑一遍，不通过就不连实例。
- **供应商自动创建**：全新系统的供应商列表是空的，脚本会按 seed 自动补齐（按名称查重，已存在的不动、不覆盖你的手工修改）。供应商改名等于新建：比如 `Grok` 改成 `xAI` 后重跑，会新建 `xAI` 并把模型改绑过去，旧的 `Grok` 留在实例上，需在 UI 里手工删。
- **模型元信息以 seed 为准**：已存在的模型若描述、图标、标签、端点、状态、匹配规则或供应商绑定与 seed 不同，会被改回 seed 的值（UI 里手工改过的也一样）。脚本新建的模型会关闭「同步官方元数据」（`sync_official=0`），免得被上游同步覆盖掉 seed 的文案。seed 里省略的字段按空值处理，比如各模型都不写 `tags` 和 `endpoints`，实例上已有的标签和自定义端点会被清空；可用端点由 new-api 按渠道类型自动推断。
- **渠道不在种子范围内**（含上游密钥，不适合进仓库）——新系统需自行添加渠道，模型与渠道的绑定会自动关联。
- **币种约定**：OpenAI / Anthropic / xAI / Google 按官方美元价填写；DeepSeek 按**国内人民币价的数字直接填**（2 元写成 `p * 2`），不做汇率折算。系统本身不做汇率换算，表达式里的数字一律按「$」扣额度，所以 DeepSeek 的额度消耗约是按美元折算的 7 倍——这是有意的决策。
- **`deepseek-v4.1-flash`**（DeepSeek V4.1 Flash，2026-09-10 发布）：官方 API 的调用名是 `deepseek-flash`，**渠道里要配模型映射 `deepseek-v4.1-flash` → `deepseek-flash`**，否则上游报模型不存在。**有意全天按国内空闲价收**：输入 1、命中 0.02、输出 4（官方高峰时段是双倍：2 / 0.04 / 8，北京时间周一至周五 9:00–12:00、14:00–18:00），不收缓存写入，1M 上下文不分档。
- **Grok 200K 长上下文阶梯**：短档 $2/$6，提示词**达到** 200K 时整个请求按 $4/$12 计费（不是超出部分才涨），所以表达式写 `len < 200000`（恰好 200,000 也属高档）。缓存命中各代不同：`grok-4.7` / `grok-4.6` $0.5/$1，`grok-4.5` $0.3/$0.6。
- `grok-4.7` 为 xAI 当前旗舰（2026-09-21 发布），`grok-4.6` 降为上一代、`grok-4.5` 为旧版；三者除 4.5 的缓存命中价外定价相同。
- **Grok Imagine**（**自定价**，官方图片 $0.02–0.05/张、视频 $0.02–0.08/秒，这里不跟）：
  - 图片 `grok-imagine-image-2.0` / `grok-imagine-image` 每张 $0.1，表达式同 GPT Image：`tier("image", fixed(0.1)) * image_count`，走 xAI 渠道的 `/v1/images/generations`。
  - 视频 `grok-imagine-video-1.5` / `-1.5-lite` / `grok-imagine-video` 每秒 $0.2，表达式 `tier("video", u("seconds") * 0.2)`：视频是异步任务，由 new-api 内置的 xAI 任务插件计费（rc.44 起），`u("seconds")` 是插件上报的秒数，结果直接是美元，不除以 100 万；任务表达式不允许 `fixed()`。提交时按请求时长预扣（不传默认 8 秒），完成后按实际时长结算；只按输出秒数收，输入图片和编辑 / 延长时的输入视频不另收，被内容审核拦截的照样收（xAI 也收）。编辑和延长只有 `grok-imagine-video` 支持。
  - 未收录 `grok-imagine-image-quality`：官方 2026-11-02 下线，之后转给 `grok-imagine-image-2.0`。
- **Gemini**（供应商名 `Google`，与 new-api 官方元数据同步一致）：按官方 Standard 档美元价。用量是 OpenAI 格式（`p` 含缓存，思考 token 计入输出），写 `cr` 把缓存命中扣出来单独计价；Google 不收缓存写入费（显式缓存另收存储时长费，表达式表达不了，不配），所以不写 `cc`。缓存命中除 `gemini-4-argon` 为 **0.05x** 外均为 0.1x。
  - `gemini-4-argon`（2026-10-13 GA）旗舰：$2/$10、命中 $0.1，1M 上下文不分档。
  - `gemini-3.1-pro-preview`：$2/$12、命中 $0.2；提示词**超过** 200K 时整个请求按 $4/$18、命中 $0.4，表达式写 `len <= 200000`（`len` 含缓存命中，大部分命中缓存也照样走长档）。
  - `gemini-3.8-flash`（2026-09-02 GA）与 `gemini-3.6-flash` 同价：$0.75/$3.75、命中 $0.075。
- **Gemini 限时价到期要手工改**（表达式没有 `year()`，没法按日期自动切换）：`gemini-4-argon` **2026-12-01** 起 $4/$20、命中 $0.2；`gemini-3.8-flash` / `gemini-3.6-flash` **2027-01-01** 起 $1.5/$7.5、命中 $0.15。基础型号和它的思考档位变体要一起改（`--check` 会检查变体与基础型号同价）。
- **Gemini 思考档位变体**（`gemini-3.1-pro-preview-low` / `-medium` / `-high`，`gemini-3.8-flash-*` 同上，`gemini-3.6-flash-*` 多一档 `-minimal`）：不是 Google 的型号 ID，是 new-api 把后缀转成 `thinking_level`，并顺带返回思考摘要，档位按官方思考文档逐型号核实。**rc.44 起要在系统设置的模型页 Gemini 分区（`/system-settings/models/gemini`）打开「思考后缀适配器」**才解析这类后缀，关着的话 `gemini-3.8-flash-high` 会原样发给上游并报模型不存在。路由和计费都回落到基础型号：渠道里只配基础型号也能用，seed 显式配变体只是为了让渠道列出变体名时模型广场能显示简介和价格。`gemini-4-argon` 不加变体：rc.44 的能力表还不认 Gemini 4，后缀会被丢掉，按默认 medium 档跑。
- `claude-opus-5-5` 为当前 Opus（2026-09-22 发布）：$4/$20，缓存写 $5、命中 $0.2（**0.05x**）。`claude-opus-5` 与 `claude-opus-4-8` 官方同价（$5/$25，缓存写 $6.25、命中 $0.5）。除 `claude-haiku-5-5` 外，Claude 在 1M 上下文内按标准价计费，无长上下文溢价，故表达式只有一档。
- `claude-haiku-5-5`（2026-10-07 发布）是 Claude 里唯一按提示词长度分档的型号：100K 以内 $0.1/$0.5，缓存写 $0.125 / $0.2、命中 $0.01；提示词**超过** 100K 时整个请求按 $0.5/$2.5 计费（缓存写 $0.625 / $1、命中 $0.05），表达式写 `len <= 100000`（Claude 的 `len` 含缓存读写，与官方「提示词长度」口径一致）。
- **模型描述**一句话写「定位 + 擅长场景」，参照官方模型页的介绍；不写「当前 / 上一代」这类会过时的说法，也不写价格——新模型发布时老模型的描述不用动。
- Claude 缓存命中价不是全系 0.1x：`claude-fable-5-1` 是 **0.025x**（$0.25），`claude-opus-5-5` 是 **0.05x**（$0.2），其余型号是 0.1x。`claude-sonnet-5-5` **按发布价配，有意不跟官方降价**：命中 $0.2（0.1x），官方 2026-10-07 下调到 $0.1（0.05x）。
- **`gpt-5.6`**：`sol`、`luna` **按发布价配，有意不跟官方降价**——`sol` $5/$30（长档 $10/$45；官方现价 $4/$20 是至少持续到 2026-11-21 的促销价），`luna` $1/$6（长档 $2/$9；官方 2026-07-30 降到 $0.2/$1.2）。`terra` 跟官方现价 $2/$12。`codex-auto-review` 无官方价，跟 terra 同价。
- **GPT Image**（`gpt-image-2.5-sunburst` / `gpt-image-2.5-flare` / `gpt-image-2`）：**自定价**，每张 $0.1，表达式 `tier("image", fixed(0.1)) * image_count`，一次请求 `n=4` 收 $0.4。官方是按 token 计价，这里不跟。
- **GPT-6 一代**（2026-09 发布）：`gpt-6-astra` 旗舰 $10/$50（长档 $20/$75），`gpt-6.1-sol` $2/$10（长档 $4/$15，2026-09-29 发布），`gpt-6-sol` 降为上一代（同价），`gpt-6-luna` $0.5/$2.5（长档 $1/$3.75，**自定价**：官方价 $0.1/$0.5 的 5 倍，与 `gpt-5.6-luna` 发布价的倍数一致）；缓存命中除 `gpt-6.1-sol` 为 **0.05x** 外均为 0.1x，缓存写入 1.25x（OpenAI 自 GPT-5.6 起收写入费，GPT-5.5 及更早不收）。长档是输入**超过** 272K 整单涨价，表达式写 `len <= 272000`。
- `claude-sonnet-5` 的 $2/$10 **已转为官方标准价**：原定 2026-09-01 涨到 $3/$15 的计划被 Anthropic 明确取消，无需再按限时价跟进。
- **后端内置计费表达式**：rc.40 自带 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`（图像计费用 `img` / `img_cr` 变量）和 `gpt-6-astra` 四条内置表达式，只作为默认值生效、不落库。脚本按模型写入不会把它们固化进库；这四个模型在 seed 里都有显式定价，以 seed 为准（后端先读已配置的表达式，没有才回落到内置值）。
- **从 seed 删掉条目 ≠ 目标系统会删**：已灌入实例的模型元信息和供应商需在 UI 里手工删；定价在默认模式下对 seed 之外的模型原样保留，只有 `--reset-pricing` 会清掉（连带清掉你手工配的其他定价，先 `--dry-run`）。
- **只用计费表达式**：rc.40 已把「按 Token（倍率）」「按次」两种旧定价模式标为弃用，表达式模式下计费不读倍率表，所以 seed 里没有 `ModelRatio` 等旧键（`--check` 会拒绝）。按次、图片、音频、视频计费也都用表达式写（`fixed()`、`image_count`、`img`、`ai` / `ao` 变量，视频任务用 `u("seconds")`）；分组倍率（GroupRatio）不是按模型的定价，不在脚本范围内。UI 里「转换为计费表达式」按钮若报 routing 校验失败，不用管它（seed 本来就是表达式）。
- 配置有变化时，重新从线上导出或直接改 `seed.json`，然后对所有实例重跑一遍。
